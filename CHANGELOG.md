# Changelog

All notable changes to this project are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions follow [semantic versioning](https://semver.org/); until 1.0, a minor version can change
the interface.

## Unreleased

### Added

- A self-hosted Jenkins update center in containers, run with Docker Compose: `uc` (generation and
  tools), `scheduler`, `repo-adapter` and `web` (Apache)
  ([Architecture](docs/architecture/overview.md)).
- Online mode, with upstream data fetched live and plugins and downloads from repo.jenkins-ci.org
  and get.jenkins.io or your own Artifactory or Artifact Keeper, and air-gapped mode, which fetches
  nothing from the internet ([Modes](docs/architecture/modes.md)).
- Version routing to tiered sites, every upstream JSON file and download index pages, generated by
  the pinned update-center2 3.18.4 with two small patches.
- Metadata signed with your own PKI: `uc pki init`, `rotate` and `show`
  ([Rotate the signing certificate](docs/how-to/rotate-signing-certificate.md)).
- Atomic publishing with validation, five retained releases and `uc rollback`
  ([Generate and roll back](docs/how-to/generate-and-roll-back.md)).
- The repo-adapter: Artifact Keeper support, and POMs, descriptions and release dates read from
  inside each plugin archive ([Repo adapter](docs/architecture/repo-adapter.md)).
- An overlay for your own blocklist and security warnings
  ([Block plugins and add warnings](docs/how-to/block-plugins-and-add-warnings.md)).
- TLS in the web container ([Enable TLS](docs/how-to/enable-tls.md)), and a download proxy mode
  for repositories controllers cannot read ([Proxy downloads](docs/how-to/proxy-downloads.md)).
- Settings in `.env`, whose generated examples list every setting. `uc config` shows each value and
  whether it is the default, and `--check` validates them
  ([Configuration](docs/reference/configuration.md)).
- First-time setup in one command, `docker compose run --rm setup`: the credential files and the
  signing keys, all owned by you ([Secrets](docs/reference/secrets.md)).
- `uc doctor` reports what the generator will see in your repository, including the cores plugins
  require that it lacks; the scheduler can record the report on `DOCTOR_SCHEDULE`
  ([Stock an air-gapped repository](docs/how-to/stock-airgapped-repository.md)).
- `uc procure stage`, `record`, `push` and `clean`: fetch the files the repository lacks from
  repo.jenkins-ci.org, or record files you place by hand, stage them in `./procurement` for review,
  push exactly what was reviewed, and clean up after
  ([Procure missing files](docs/how-to/procure-missing-files.md)). `uc doctor` and each
  `uc procure` command end with the next step.
- An example Jenkins pipeline that runs procurement with an approval before the push
  ([Run procurement from a pipeline](docs/how-to/run-procurement-from-a-pipeline.md)).
- A public `status.json` to monitor ([Monitor](docs/how-to/monitor.md)); `uc --version` and its
  `uc_version` name the release the uc image was built as.
- Releases: uc and web images on GHCR for linux/amd64 and linux/arm64, signed with cosign, with
  build-provenance and SBOM attestations, and an air-gapped bundle per architecture with a signed
  `SHA256SUMS` ([Verify a release](docs/how-to/verify-a-release.md)).
- Third-party notices in the uc image, `/opt/uc/licenses/`.
- Unit, routing and end-to-end tests, run by CI on every pull request; this documentation.
